# Git Flow

長く使うブランチが2本あります。

| ブランチ | 役割 |
| --- | --- |
| `main` | リリースしたものだけ。リリースごとに [[tag|タグ]]（v1.0.0）を付ける |
| `develop` | 次のリリースに向けた開発の統合先 |

作業用のブランチは3種類です。

| 種類 | どこから作る | どこへマージ |
| --- | --- | --- |
| `feature/〜` | develop | develop |
| `release/〜` | develop | main と develop |
| `hotfix/〜` | main | main と develop |

マージは `--no-ff` で、マージコミットを残すのが慣例です（どの機能・リリースを入れたかが履歴に残る）。

> 手順が多いぶん、「v1.0 を保守しながら v2.0 を作る」ような製品に向いています。Web サービスなら GitHub Flow の方がシンプルです。
