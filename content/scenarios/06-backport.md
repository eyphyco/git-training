# リリース済みの版にも修正を届ける

製品によっては、新しい版（2.0）の開発と並行して、出したあとの版（1.x）のサポートを続けます。main で直したバグを古い版にも入れることを **backport（移植）** と呼びます。

- 古い版のブランチ（`release/1.x`）に切り替える
- 直したコミットだけを `git cherry-pick -x <コミット>` でコピーする
- コンフリクトしたら、古い版に合わせて解消する
- タグ（`v1.0.1`）を付けて出す

`-x` を付けると、コミットメッセージの最後に `(cherry picked from commit <元の ID>)` が残ります。同じ修正が複数のブランチにあっても、元のコミットからたどれます。

main を release/1.x にマージしてはいけません。2.0 の未完成の変更まで 1.x に入ってしまいます。
